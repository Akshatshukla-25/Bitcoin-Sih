## 1. System Invariants & Non-Negotiables

1. **100% Offline Air-Gapped Operation**:
   - Zero runtime HTTP/DNS/socket network requests.
   - All GeoIP lookups resolve against the local offline CIDR database in `data/geoip/`.
   - Python dependencies must be standard, offline-installable packages in `requirements.txt`.
   - Frontend is Next.js 14 with all static fonts and packages bundled locally (zero CDN dependencies).
2. **Deterministic Reproducibility**:
   - Any script utilizing pseudo-randomness must explicitly seed both `random.seed(42)` and `numpy.random.seed(42)`.
   - All community clustering (Louvain) and dataframe sorting operations use canonical lexical tie-breaking (`mergesort` with secondary keys).
   - Re-running `python3 pipeline.py` must produce byte-identical files in `data/` and `reports/` (verified via `git status -s`).
3. **Tripartite Graph Schema & Edge Direction Invariant**:
   - Graph type: `networkx.MultiDiGraph`.
   - Node classes (`node_type`):
     - `wallet`: Bitcoin address (Base58 or Bech32).
     - `transaction`: 64-char transaction hash (`txid`).
     - `ip`: IPv4 address string.
   - Directed Edge Semantics (Strictly enforced by `graph_builder.validate_graph`):
     - `wallet -> tx` (`funds`): Amount in BTC contributed by the input wallet UTXO.
     - `tx -> wallet` (`pays`): Amount in BTC disbursed to the output wallet UTXO.
     - `ip -> tx` (`broadcasts`): Source IP broadcasting the transaction to the P2P gossip network.
     - `tx -> ip` (`relays_to`): Peer node receiving the transaction relay.
   - **Never invert or modify these edge directions** — downstream feature extraction (`graph_signals.py`) and visualization rely directly on this convention.
4. **Data Isolation**:
   - Production artifacts reside in `data/` and `reports/`.
   - The FastAPI backend serves these static artifacts via `api/data_loader.py` with thread-safe file signature caching (`_CACHE_LOCK`).

### Workflow 1: Synthetic Data Generation & Typology Planting (`data_gen.py`)
1. **Inputs**: `--count` (default: 683), `--seed` (default: 42).
2. **Execution Steps**:
   - Seeds `random` and `np.random` with seed 42.
   - Generates background "normal" organic Bitcoin spending (multi-input, randomized non-round amounts, variable delays from minutes to days, persistent home broadcast IPs).
   - Plants three distinct adversarial laundering patterns:
     - **Peel Chains**: Long sequential chains ($5-10$ hops) where each transaction retains a small skim ($2\%-8\%$) and forwards the remaining balance within tight intervals ($<30\text{ min}$).
     - **Mixers / Tumblers**: Burst fan-outs (one source wallet sending to $5-15$ intermediate child wallets simultaneously within minutes) followed by delayed consolidation into exit sink wallets.
     - **Rapid Cash-Outs**: Brand new, zero-history wallets receiving substantial lump sums ($>1.0\text{ BTC}$) and extracting $>95\%$ of funds within 10 minutes across $1-3$ rapid hops to known exit nodes.
   - Enriches each transaction with network-layer telemetry: `src_ip`, `src_port`, `dst_ip`, `dst_port` selected from realistic CIDRs.
3. **Outputs**: `data/transactions.csv` and `data/transactions.json` (also mirrored to root).

---

### Workflow 2: Tripartite Graph Construction & Validation (`graph_builder.py`)
1. **Inputs**: `data/transactions.csv`.
2. **Execution Steps**:
   - Parses and validates transaction records via `transaction_schema.py`.
   - Initializes an empty `networkx.MultiDiGraph`.
   - For every transaction record $T$:
     - Adds node $T$ with `node_type="transaction"`, `total_input_amount`, `fee`, `script_type`.
     - For each input wallet entry $\{W_{in}, \text{amt}\}$: adds node $W_{in}$ with `node_type="wallet"` and directed edge $W_{in} \xrightarrow{\text{funds}} T$ weighted by satoshi amount.
     - For each output wallet entry $\{W_{out}, \text{amt}\}$: adds node $W_{out}$ with `node_type="wallet"` and directed edge $T \xrightarrow{\text{pays}} W_{out}$ weighted by satoshi amount.
     - Adds source node $IP_{src}$ with `node_type="ip"` and directed edge $IP_{src} \xrightarrow{\text{broadcasts}} T$.
     - Adds destination node $IP_{dst}$ with `node_type="ip"` and directed edge $T \xrightarrow{\text{relays_to}} IP_{dst}$.
   - Runs `validate_graph()`: verifies all nodes belong to $\{\text{wallet}, \text{transaction}, \text{ip}\}$, checks that all edges strictly match edge direction conventions, and ensures every transaction node has both incoming (`funds`, `broadcasts`) and outgoing (`pays`, `relays_to`) edges.
3. **Outputs**: `data/graph.gml` and `data/graph.json`.

---

### Workflow 3: Multi-Heuristic Entity Clustering (`clustering.py`)
1. **Inputs**: `transactions.csv`, `data/features.csv`.
2. **Execution Steps**:
   - **Union-Find Disjoint Set Union (DSU)**:
     - **Common-Input-Ownership Heuristic (CIOH - 95% Confidence)**: If a transaction contains multiple input wallets $[W_1, W_2, \dots, W_k]$, they are unioned into a single entity cluster: $\text{Union}(W_1, W_i)$.
     - **Chronological Change-Address Detection (CADH - 85% Confidence)**: Evaluates address freshness strictly prior to current transaction timestamp (zero temporal lookahead).
     - **Peel-Chain Continuation Heuristic (PCCH - 90% Confidence)**: If a transaction has 2 fresh outputs with asymmetric forward vs. skim ratios ($>85\%$ forwarded to one address, $2-8\%$ skimmed to the other), unions the forward spine address to the sender.
   - **Community Detection**:
     - Constructs an undirected co-spending & flow projection graph.
     - Computes Louvain modularity communities (`nx.community.louvain_communities(G, seed=42)`) with canonical lexical tie-breaking.
   - **Cluster Confidence & Disagreement Scoring**:
     - Assigns a heuristic confidence score $[0.0, 1.0]$ based on links.
     - Flags `has_disagreement = True` if multi-input co-spending conflicts with community modularity boundaries.
3. **Outputs**: `data/wallet_clusters.csv` and `data/clusters.json`.

---

### Workflow 4: Feature Store Engineering (`features.py` & `graph_signals.py`)
1. **Inputs**: `transactions`, `data/graph.gml`.
2. **Execution Steps**:
   - Iterates through all unique wallets in the tripartite graph.
   - Computes **45 numerical & categorical features** per wallet:
     - **Volume & Turnover**: `total_received_amount`, `total_sent_amount`, `net_balance`, `turnover_ratio` ($V_{sent} / V_{received}$).
     - **Velocity & Temporal Extraction**: Minimum drain minutes, `forwarded_pct_10m`, `forwarded_pct_30m`, `avg_hop_interval_mins`, `wallet_age_hours`.
     - **Network Infrastructure**: Unique broadcast IPs, unique destination IPs, unique countries (`unique_countries_count`), unique Autonomous System Numbers (`unique_asns_count`), `dominant_country`, `dominant_asn`.
     - **Graph Centrality**: Value-weighted Betweenness Centrality (inverted distance $\frac{1}{\text{amount} + 10^{-6}}$) and PageRank on the projected wallet flow graph.
     - **P2P Timing Entropy**: Shannon entropy of transaction broadcast hours $[0, 23]$ normalized to $[0.0, 1.0]$ (low entropy denotes automated bot schedules; high entropy denotes human behavior).
3. **Outputs**: `data/features.csv`.

---

### Workflow 5: Unsupervised Anomaly Detection Ensemble (`models.py`)
1. **Inputs**: `data/features.csv`, `--seed 42`.
2. **Execution Steps**:
   - Selects 26 continuous numerical features from `features.csv` (excluding wallet addresses and ground truth).
   - Applies `RobustScaler` to handle extreme outliers and skew.
   - Fits three complementary unsupervised anomaly detectors with conservative regulatory prior contamination $= 0.10$ ($10\%$):
     1. **Isolation Forest** (`n_estimators=150`, `random_state=42`): Partitions feature space using random orthogonal hyperplanes. Scores are inverted decision function values.
     2. **Local Outlier Factor (LOF)** (`n_neighbors=150`, `novelty=True`): Computes local reachability density relative to $k$-nearest neighbors.
     3. **Robust Mahalanobis Distance**: Fits `LedoitWolf(assume_centered=False)` shrinkage covariance to compute regularized ellipsoidal distance: $D_M(x) = \sqrt{(x - \mu)^T \Sigma^{-1} (x - \mu)}$.
   - **Variance-Standardized Blending**:
     - Computes z-scores for each model's output distribution: $z_m = \frac{s_m - \mu_m}{\sigma_m}$.
     - Meta-ensemble score: $z_{\text{blend}} = \frac{z_{IF} + z_{LOF} + z_{Mahal}}{3}$.
     - Min-max scales $z_{\text{blend}}$ into a continuous interval $[0.0, 1.0]$ (`ensemble_anomaly_score`).
3. **Outputs**: `data/anomaly_scores.csv` and `data/model_artifacts.joblib`.

---

### Workflow 6: Composite Risk Scoring, Banding & Reason Codes (`scoring.py`)
1. **Inputs**: `data/anomaly_scores.csv`, `data/wallet_clusters.csv`, `data/clusters.json`.
2. **Execution Steps**:
   - Calculates cluster-level risk as the mean ML anomaly score across all wallets in that cluster.
   - Computes the **Composite Risk Score** $[0.0, 100.0]$ via weighted linear combination:
     $$\text{Composite} = 0.50 \cdot (\text{ML Score} \cdot 100) + 0.30 \cdot (\text{Graph Structural Risk} \cdot 100) + 0.20 \cdot (\text{Cluster Mean Risk} \cdot 100)$$
   - Categorizes each wallet into one of 4 statutory policy bands:
     - **CRITICAL** (Score $\ge 60.0$): Immediate freeze recommendation; high forensic certainty.
     - **HIGH** ($50.0 \le \text{Score} < 60.0$): Priority escalation; urgent human review.
     - **MEDIUM** ($35.0 \le \text{Score} < 50.0$): Surveillance watch; triage queue.
     - **LOW** (Score $< 35.0$): Normal baseline traffic.
   - Evaluates rule predicates to assign semicolon-delimited reason codes:
     - `PEEL_CHAIN`: High peel skim signal with low hop interval.
     - `MIXER_FANOUT`: Extreme fanout burst with multiple counterparties.
     - `RAPID_CASHOUT`: $>95\%$ balance forwarded in $<10$ minutes from fresh wallet.
     - `CROSS_BORDER_HOP`: Transactions span $\ge 3$ distinct geographic countries or ASNs.
     - `NEW_WALLET_HIGH_VOLUME`: Wallet age $<1$ hour with total received $>3.0$ BTC.
3. **Outputs**: `data/scored_entities.csv` and `data/alerts.json`.

---

### Workflow 7: SHAP Explainability & SAR Narrative Generation (`explain.py` & `narrative.py`)
1. **Inputs**: `data/scored_entities.csv`, `data/model_artifacts.joblib`, `data/transactions.json`.
2. **Execution Steps**:
   - **SHAP Computation**: Initializes `shap.TreeExplainer` on the fitted `IsolationForest` model. Calculates additive Shapley value vectors $\phi_i$ for every wallet across all 26 features. Saves top 5 positive attribution features per wallet into `data/explanations.json`.
   - **Deterministic SAR Generation**:
     - Extracts authentic transaction timestamps from `data/transactions.json` for each wallet to establish `wallet_generated_at` (avoiding wall-clock non-determinism).
     - Synthesizes a structured 3-paragraph plain-language brief summarizing: (1) Primary alert reason and composite score, (2) Top SHAP feature attributions and geographic hops, (3) Statutory FIU-IND recommendation.
     - Pre-caches standardized Suspicious Activity Report (SAR / STR) JSON documents keyed by wallet address (`SAR-NTRO-YYYY-<HASH>`).
3. **Outputs**: `data/explanations.json` and `data/cached_narratives.json`.

---

### Workflow 8: Model Comparison & Ground-Truth Policy Evaluation (`model_comparison.py` & `evaluate.py`)
1. **Inputs**: `data/features.csv`, `data/scored_entities.csv`, `--seed 42`.
2. **Execution Steps**:
   - **Model Comparison Benchmark**: Under empirical contamination calibration matching the ground-truth anomaly prior ($35.62\%$), benchmarks 8 algorithms: CBLOF, PCA, LOF, k-NN, 3-Model Ensemble, Robust Mahalanobis, Isolation Forest, and HBOS. Computes ROC-AUC, PR-AUC, F1-Score, Precision, Recall. Saves to `reports/model_comparison.csv`.
   - **Operational Policy Evaluation**: Evaluates composite detection engine against ground truth at MEDIUM ($\ge 35$), HIGH ($\ge 50$), and CRITICAL ($\ge 60$) thresholds. Computes True Positives (TP), False Positives (FP), True Negatives (TN), False Negatives (FN), Precision, Recall, Specificity, F1, ROC curve coordinates, and PR curve coordinates.
   - Generates high-contrast forensic visualization plots (`confusion_matrix.png`, `roc_curve.png`).
3. **Outputs**: `reports/model_comparison.csv`, `reports/evaluation_metrics.csv`, and PNG figures.

---

### Workflow 9: Backend Artifact Loading & Thread-Safe Caching (`api/data_loader.py`)
1. **Inputs**: File system artifacts in `data/` and `reports/`.
2. **Execution Steps**:
   - Implements `load_data_bundle()` protected by an re-entrant threading lock `_CACHE_LOCK`.
   - Computes file signature tuple `(filename, mtime_ns, file_size)` across all 9 authoritative artifact files (`_artifact_signature()`).
   - If cache is empty or file signature changes on disk (e.g. after pipeline re-run):
     - Reloads CSV and JSON files using defensive type checking (`_read_csv`, `_read_json`).
     - Validates required columns in DataFrames and schema compliance of transactions.
     - Recursively sanitizes non-finite floats (`NaN`, `inf`, `-inf`) to `None` via `clean_nan()` to ensure valid RFC 8259 JSON compliance.
     - Updates `_DATA_CACHE` and `_CACHE_SIGNATURE`.
   - Exposes REST routes via FastAPI sub-routers (`overview`, `alerts`, `cases`, `network`, `models`, `evaluation`).

## 4. Data Schemas & Column Dictionaries

### A. `transactions.csv` / `transactions.json`
- `timestamp`: ISO-8601 string (`2025-01-01T...`).
- `txid`: 64-character SHA-256 transaction hash.
- `input_wallet_addresses`: JSON list of `{"address": str, "amount": float}`.
- `output_wallet_addresses`: JSON list of `{"address": str, "amount": float}`.
- `total_input_amount`: Float satoshi balance in BTC.
- `fee`: Float miner fee in BTC.
- `script_type`: Script standard (`P2PKH`, `P2SH`, `P2WPKH`, `P2WSH`).
- `src_ip`, `src_port`: Originating broadcast node IP and port.
- `dst_ip`, `dst_port`: First-hop peer relay node IP and port.
- `_ground_truth_label`: Class label (`normal`, `peel_chain`, `mixer`, `rapid_cashout`).

### B. `features.csv` (45 Total Columns)
1. **Identifiers & Counts**: `wallet_address`, `tx_count`, `in_degree`, `out_degree`, `degree_ratio`, `fanin_count`, `fanout_count`.
2. **Financial Volumes & Turnover**: `total_received_amount`, `total_sent_amount`, `net_balance`, `turnover_ratio` ($\frac{\text{sent}}{\text{received}}$).
3. **Temporal Dynamics**: `avg_hop_interval_mins`, `median_hop_interval_mins`, `min_hop_interval_mins`, `max_hop_interval_mins`, `min_drain_minutes`, `wallet_age_hours`.
4. **Extraction Velocity**: `forwarded_pct_10m`, `forwarded_pct_30m`, `forwarded_pct_60m`, `forwarded_pct_120m`, `transient_velocity`, `velocity_drain_score`.
5. **Typology Signals**: `peel_skim_ratio`, `peel_signal`, `fanout_burst_signal`, `fanin_burst_signal`, `is_peel_chain_node`, `is_mixer_hub`, `is_mixer_intermediate`, `is_rapid_cashout_node`.
6. **Network & Graph Topology**: `unique_counterparties`, `unique_ips_count`, `unique_src_ips_count`, `unique_countries_count`, `unique_src_countries_count`, `unique_asns_count`, `unique_src_asns_count`, `dominant_country`, `dominant_asn`, `timestamp_entropy`, `betweenness_centrality`, `pagerank`.
7. **Evaluation Labels**: `ground_truth_label`, `is_planted_anomaly` (Binary: 1 for illicit, 0 for normal).

### C. `scored_entities.csv`
Contains all feature columns merged with:
- `ensemble_anomaly_score`: Continuous raw ML anomaly score $[0.0, 1.0]$.
- `composite_risk_score`: Scaled composite score $[0.0, 100.0]$:
  $$\text{Composite} = 0.50 \cdot (\text{ML} \cdot 100) + 0.30 \cdot (\text{GraphStructural} \cdot 100) + 0.20 \cdot (\text{CommunityRisk} \cdot 100)$$
- `risk_band`: Categorical risk tier:
  - `CRITICAL`: Score $\ge 60.0$
  - `HIGH`: $50.0 \le \text{Score} < 60.0$
  - `MEDIUM`: $35.0 \le \text{Score} < 50.0$
  - `LOW`: $\text{Score} < 35.0$
- `confidence_score`: Forensic confidence $[0.0, 1.0]$ based on feature coverage and cluster cohesion.
- `reason_codes`: Semicolon-delimited triggered indicators (`PEEL_CHAIN`, `MIXER_FANOUT`, `RAPID_CASHOUT`, `CROSS_BORDER_HOP`, `NEW_WALLET_HIGH_VOLUME`).

## 5. FastAPI Backend API Contract

All endpoints are hosted at `http://127.0.0.1:8000` and documented at `/docs`:

### 1. `GET /api/overview`
- **Purpose**: System KPIs, score histogram, reason code frequency, daily volume timeline.

### 2. `GET /api/alerts`
- **Query Params**: `bands`, `min_score`, `country`, `search`, `limit`, `offset`, `sort_by`, `sort_dir`.

### 3. `GET /api/cases/{wallet_address}`
- **Purpose**: Comprehensive forensic case profile, SHAP breakdown, counterparty clusters, directed transaction history.

### 4. `GET /api/cases/{wallet_address}/sar`
- **Purpose**: Downloadable official SAR/STR JSON export package.

### 5. `GET /api/network`
- **Query Params**: `scope` (`top30` | `ego`), `wallet` (required when `scope=ego`).

### 6. `GET /api/models`
- **Purpose**: SHAP feature importance rankings, score distribution statistics per model, and IF vs Mahalanobis 2D scatter points.

### 7. `GET /api/evaluation`
- **Purpose**: Algorithm comparison benchmark table, confusion matrices for the 3 triage tiers, and downsampled ROC/PR curve points.

### 8. `GET /api/download/{doc_name}`
- **Purpose**: Direct download of documentation (`team-explainer`, `team-explainer-txt`, `human-context`, `human-context-txt`, `ai-context`).

### 9. `GET /api/health`
- **Purpose**: Liveness probe returning system readiness, offline status, and entity counts.
